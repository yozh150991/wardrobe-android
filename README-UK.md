# Wardrobe 0.4.0 — Firebase підключено в конфігурації

Пакет містить повний вихідний проєкт 0.4.0 з наданим `google-services.json`: Firebase project **wardrobe-75fea**, Android package **com.familywardrobe.app**. Версія застосунку залишається 0.4.0-auth (versionCode 6); функціональні зміни тут — лише клієнтська конфігурація. Початковий універсальний пакет авторизації та UI-пакет 0.3.0 залишені окремо.

## Якщо вже маєш проєкт 0.4.0

Щоб додати конфігурацію до свого проєкту й зберегти власні правки, розпакуй цей архів в окрему папку. У PowerShell із розпакованої папки виконай:

```powershell
.\connect-firebase.ps1 -ProjectPath 'C:\path\to\wardrobe-android' -CheckOnly
.\connect-firebase.ps1 -ProjectPath 'C:\path\to\wardrobe-android'
```

Замінити шлях потрібно на папку **твого** проєкту. Скрипт додає тільки `app/google-services.json`; ідентичний файл пропускає, при іншій конфігурації зупиняється без перезапису. Код і UI-правки не змінює. Альтернатива: скопіюй `wardrobe-android/app/google-services.json` із цього архіву в `app` свого проєкту.

Якщо ще маєш 0.3.0 зі своїми правками, спочатку застосуй `wardrobe-auth-update-0.4.0.zip`, потім підключи конфігурацію командою вище. У цьому архіві немає повторного патча авторизації.

## Якщо використовуєш повний проєкт із цього пакета

Відкрий папку `wardrobe-android` у Android Studio. Конфігурація вже лежить у `app/google-services.json`, Gradle-плагін підхопить її під час синхронізації.

Для збірки на Windows потрібні JDK 17 (або 21), Android SDK 35 та інтернет для залежностей. У PowerShell у папці `wardrobe-android`:

```powershell
.\build-apk.ps1
```

Або збери APK через Android Studio. Очікуваний вихідний файл:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Установлюй поверх наявного застосунку з тим самим applicationId та ключем підпису, щоб зберегти локальні дані. Перед переходом можна експортувати ZIP-копію гардероба з поточної версії.

## Перший тест

1. Відкрий застосунок: перший екран — вхід.
2. Створи акаунт із власним email і паролем від 12 символів. За наявності старих речей підтвердь їхню прив’язку до потрібного акаунта.
3. Вийди та увійди знову; перевір, що речі залишилися. У другому акаунті вони не повинні відображатися.
4. Перевір неправильний пароль, відсутність мережі та відновлення через «Забули пароль?». Після зміни пароля за посиланням увійди з новим паролем.

Email/Password на наданому скриншоті має статус Enabled. Налаштування password policy (12–4096, Require), захисту від визначення зареєстрованих email і reset-шаблону ще перевір у Firebase Console; деталі — `wardrobe-android/AUTHENTICATION.md`.

## Межі перевірки

Перевірено структуру JSON, відповідність package/project/app ID, точну передачу файла та підключення залежностей у коді. У цьому середовищі відсутні Android SDK/Gradle і стандартний javac launcher: збірка зупиняється до запуску Gradle. **APK не зібрано; реальні реєстрацію, вхід і листи ще не перевірено.** PowerShell-скрипт тут також не запускався. Серверні налаштування не змінювалися програмно, тестові акаунти/листи не створювалися.
