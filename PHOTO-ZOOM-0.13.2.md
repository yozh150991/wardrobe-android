# PHOTO-02 — перегляд і зум збереженого фото

0.13.2-release, code 21. Запит користувача 08.10.2026: роздивитися деталі одягу,
які погано видно на картці. Реалізація у вихідному коді; native-приймання відкрите.

## Як користуватися

Натисніть фото з лупою в каталозі або «Хочу купити», а також на екрані деталей.
Відкриється збережене фото на весь екран. Розведіть пальці для збільшення 1–5×,
пересувайте збільшене фото. Подвійний дотик вмикає 3× біля точки натискання;
на збільшеному фото повертає fit. Кнопки +/−/fit доступні без жестів.
Закрити можна хрестиком або системним Back. Повторне відкриття починає з fit.

Текстова частина картки відкриває деталі, як раніше. У режимі вибору кількох
речей натискання фото продовжує вибирати річ; лупа й зум у ньому вимкнені.
Змінений розмір viewport скидає зум і позицію, щоб фото лишалося досяжним.

## Реалізація і дані

`PhotoViewer.kt`: спільний read-only діалог та інтеграція картки через
`ZoomableItemPhoto`. Виклики: `CatalogScreen.kt`, `Ui.kt` Detail,
`WishlistScreen.kt` картки/WishDetail. Loading, missing photo й Retry визначені.
Кнопки 48 dp, локалізація UA/EN/PL/fallback, TalkBack actions для зуму й руху.
Нейтральне сіре тло показує прозорі cutout без прив’язки до кольору теми.

`PhotoZoomRules.java` використовує `PhotoViewportRules.viewport`: fit,
прив’язка точки під пальцями, обмеження pan і масштабу. Rotation gesture
не обертає й не редагує зображення. Стан і завантаження прив’язані до
фото/PhotoStore акаунта; після зміни акаунта старий перегляд не переноситься.

Завантажується наявний bitmap із PhotoStore, без нового thumbnail, копії або
перезаписування. Масштабування не створює втрачені деталі/роздільність.
Дані, PhotoStore, оригінали, чернетки, Room/backup 8, cloud і permissions незмінні.

## Фактичні перевірки

- 225 Java assertions проти production-геометрії: anchor/pan, min/max/reset,
  portrait/landscape/square/тонкі фото, межі кадру та невалідні координати.
- 16 host-наборів пройшли; `docs/history/HOST-VALIDATION-0.13.2.json`.
- `PhotoZoomRulesTest.java` — підготовлений JUnit wrapper, не запущений Gradle.
- Kotlin/Compose/KSP, JUnit/lint, Android/Firebase, APK, UI та Windows/PowerShell
  не виконані: Gradle bootstrap — Network is unreachable.

## Native-матриця — NOT RUN

| Сценарій | Очікування |
| --- | --- |
| Тап фото каталогу / власної речі | Повний екран; текст картки й далі відкриває деталі. |
| Wishlist product / WishDetail / фото потреби | Той самий переглядач, коректне фото/назва. |
| Вибір кількох речей | Фото перемикає вибір; переглядач не відкривається. |
| Pinch, pan, double tap | 1–5×, прив’язка до пальців, 3×/fit, без виходу за межі фото. |
| Швидкі +/−/fit | Межі витримані; fit повертає ціле фото й центр. |
| Portrait/landscape і поворот пристрою | Фото уміщується, кнопки доступні, масштаб скидається до fit. |
| PNG із прозорістю, JPG, низька роздільність | Правильні пропорції, зум наявного файлу без зміни байтів. |
| Missing/loading/retry | Close/Back доступні, немає завислого progress після помилки. |
| Back/Close/повторне відкриття | Повернення до того самого екрана/прокрутки; новий перегляд у fit. |
| Зміна фото/акаунта під час завантаження | Немає старого зображення або результату іншого акаунта. |
| UA/EN/PL, теми, довга назва, 320–412 dp, 200% шрифт | Текст і кнопки досяжні, немає накладань чи обрізаних дій. |
| TalkBack | Фото й назва зрозумілі; зум/fit/рух/закриття доступні без pinch. |
| Перегляд до/після Save/sync/backup | Файли й дані не змінені діями перегляду. |

До виконання матриці PHOTO-02 має статус `verify`. Після цього — PHOTO-01,
