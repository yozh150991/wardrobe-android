## Data and behavior contracts

- Version code 14, version name 0.10.0-ux. Room schema 7, its registered migration chain and portable backup format 7 remain unchanged. Original exported schema 2 is retained. No destructive migration, dependency upgrade or simulated schema export was introduced.
- Final saved garments keep the committed final photo. Raw imported images and unused candidates are removed after commit once no saved record, shared reference or unfinished queue entry needs them. Drafts and pending/failed imports retain the originals required to continue. Masking changes alpha only and never recolors garment RGB or overwrites the saved source.
- Owned, wanted, planned and actual wear remain separate. Purchase history, original Need/budget, guarded undo, shared capsule references and strict automatic recommendation rules retain the existing repository contracts. ISO storage dates are unchanged; localization affects display.
- Backup confirmation is bound to the SHA-256 of the exact inspected ZIP stream, including buffering and archive tail. Restore compares the fingerprint before copying final photos or starting its transaction. Verification writes no wardrobe data. Restore staging remains temporary and is cleaned on failure. No archive creation date is invented.
- UI return frames, pins, generated daily results and review-session deferrals are view state; they are not added to portable backups. Foreground cancellation is available only for interruptible operations. Database commits/restores finish atomically; scheduled work continues under the account/revision guards and common write lock.
- Supplied Firebase configuration and SDK/signing files are protected by the updater. This is a source update; it does not directly operate on an installed phone database.

## Required native acceptance

Run before distributing an APK. These are acceptance steps, not reported passes.

1. Build with JDK 17/21 and Android SDK 35: `bash build-apk.sh testDebugUnitTest lintDebug assembleDebug` (or the PowerShell equivalent). Run `connectedDebugAndroidTest` on a test device/emulator. Generate and validate genuine Room schema 7 with KSP; do not substitute a hand-written schema hash. Run both rule wrappers and all previous instrumentation tests.
2. UX-01: catalog with query/category/scroll → item → edit → Save/Back; daily custom result/replacement/pins → details → Back; calendar date → details → Back; capsule/packing → details → Back. Confirm exact origin and conditions survive rotation and saved-instance restoration. Confirm active-wardrobe/account changes cannot recover another account's route or draft.
3. UX-02/03: revoke SAF folder/file access, return a malformed ZIP, fill storage, change capsule packing before Save and cancel photo/import/export/verify operations. Check localized recovery actions and retained fields, no stale photo result, no success notification after cancellation, and cleanup of partial documents/candidates. A provider that cannot delete a partial document must show the corresponding message. Browse catalog/details during foreground export and scheduled copy; writes must remain serialized.
4. UX-04/05/06: start empty; first add an accessory, a dress or a jumpsuit. Dress/jumpsuit + shoes must qualify. Test unavailable shoes, empty capsule, insufficient packed subset, cold without outerwear, season conflict, pinned conflict, repeats, exclusions and hidden feedback. Confirm each action changes only the selected rule and never silently uses unavailable or excluded items. On a 360dp viewport at default text size, inspect the first result immediately below the conditions summary.
5. UX-07: ordinary content scrolling must not move the collage. Switch to Composition and test drag/pinch, front order, background and button adjustments; Undo must restore the preceding change. Reset requires confirmation. Save remains reachable with keyboard visible; blank name receives focus. For an identical item set, verify Open existing versus explicitly Update existing, including layout/background persistence.
6. UX-08: enqueue five reviewable photos with a failed and a processing row between them. Save and next must visit each ready row once, with correct progress. Defer and return via Queue; failed rows remain retryable. Rotate, leave to details and restore an unsaved review. Copy only selected previous fields. Capture up to 20 frames without a modal after every shot. Confirm committed raw originals are removed, final/shared photos remain, and unsaved or failed queue photos are retained.
7. UX-09: portrait/landscape/EXIF photos; direct crop edges/corners; sliders; 1–8× pan/zoom; brush sizes; erase/restore; original-source switch; undo per drag; before/after; Apply and Cancel. Check finger-to-pixel alignment and crop bounds near all edges, and stale-preview suppression when source changes. Inspect full-resolution final pixels; RGB values must remain unchanged by alpha-only masking.
8. UX-10/13: calendar, capsule outfits/extras and manual-editor selectors with long names and a large collection. Search, all 13 categories, thumbnail recognition, labelled full-row toggle and accurate selected count. Tap label and checkbox area separately: each tap toggles once. Save three daily variants with editable, distinguishable names.
9. UX-11: actual running, queued, waiting and failed WorkManager states; successful copied-file verification and lost folder permission. Choose a ZIP, verify shown counts, then confirm additive restore. Replace the bytes at the same URI between preview and confirmation: import must reject before any DB/photo write and clean staging. Confirm sign-out or folder-revision changes cannot complete a stale worker success.
10. UX-12/14: needs without photos must not reserve a photo block. Test all three filters, search, Found product, preserved original requirements/budget, purchase and guarded Undo. Calendar planned appearance must match saved details; a different recorded actual-wear set must show its own content. Test localized dates in UA/EN/PL, including year boundaries; stored ISO dates and wear counts must remain unchanged.
11. Inspect 320/360/390dp widths, light/dark modes and 100/150/200% text, keyboard/insets, focus order, image labels, live operation messages and full-row checkbox/radio/switch state with TalkBack. Check the actual 48dp touch areas, canvas overflow and image-memory behavior on a modest Android device. A code/contrast check does not establish native accessibility or usability.
