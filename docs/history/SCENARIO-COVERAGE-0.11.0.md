# Покриття погоджених сценаріїв — Wardrobe 0.11.0

Дата: 2 жовтня 2026. База оновлення: 0.10.0-ux. Version code 15, Room 8, ZIP format 8.

Усі вимоги семи блоків мають реалізацію в Android-коді та критерії приймання нижче. Це **не означає**, що весь застосунок перевірено на пристрої: APK не зібрано; Kotlin/Compose/KSP, Android-тести й реальний Firebase не запускалися. Хмарний клієнт потребує активації сервісів і правил у вашому проєкті. До завершення цих перевірок статус релізу — **джерельний пакет для збірки й приймання**, а не готовий перевірений APK.

## Фактично виконані перевірки

`python3 tools/run_host_checks.py` запускає 13 наборів. Результати містяться в `HOST-VALIDATION-0.11.0.json`. Вони перевіряють XML, локалізації, посилання ресурсів і DAO SQL, компілюють **виробничі Java-правила** та виконують **SQL справжніх міграцій** в SQLite. Вони не компілюють Kotlin і не виконують Android.

Нові перевірки `check_scenarios.py`: 294 Java-перевірки рішень sync, обірваного підтвердження, шляху акаунта, різноманіття натхнення й закріплень; міграція 2→8 зі збереженням наявних рядків; 42 тригери; відкриття DB після закриття; відкат даних і черги разом; пригнічення повторного upload після застосування хмари; пізніші зміни під час upload; каскади журналу й запису скасування. Перевірено синтаксис `cloud/rules.test.mjs` через `node --check`.

Спроба `bash build-apk.sh testDebugUnitTest lintDebug assembleDebug` зупинилася з повідомленням про відсутність повного JDK. Gradle/Kotlin/KSP/Android SDK не виконувались. Новий APK у пакеті відсутній.

## Обмеження безпечного скасування

Скасування покупки не видаляє пізніші правки, носіння чи зв’язок із капсулою. Залежність потрібно прибрати відповідною явною дією; інтерфейс пояснює причину. Для покупок, виконаних до 0.11.0, немає точного запису початкової власної речі: небезпечне автоматичне скасування не пропонується. Історія старих покупок і самі речі зберігаються. Нові покупки мають запис скасування, включений у backup і sync.

Повернення кандидата до потреби зберігає попередній товар у журналі. Видалення самого бажання є окремою підтвердженою дією й видаляє його журнал; фото, що все ще потрібні збереженому образу або іншому запису, залишаються.

## Команди Android-приймання

З повним JDK 17/21, Android SDK 35 і своїм Firebase-конфігом у каталозі `wardrobe-android`:

```bash
bash build-apk.sh testDebugUnitTest lintDebug assembleDebug
bash build-apk.sh connectedDebugAndroidTest
```

На Windows використайте `build-apk.ps1` з тими самими Gradle tasks. Не видаляйте встановлений застосунок перед оновленням. Для збереження даних потрібний той самий ключ підпису.

Додані `ScenarioPersistenceTest` і `ScenarioRulesTest`; розширено `EditorDraftStoreTest`. Для Firebase виконайте `cloud/npm test` згідно з `CLOUD-SETUP-UK.md`. Окремо пройдіть усі UI-рядки цієї таблиці при 100%/200% шрифті, з клавіатурою й TalkBack. Позначайте проходження тільки після фактичного запуску.
