# Перевірка Wardrobe 0.4.1 — 1 жовтня 2026

Повна команда `testDebugUnitTest lintDebug assembleDebug` завершилася з `BUILD SUCCESSFUL`: 56 виконаних задач. Для перевірки встановлено повний JDK 17, Android SDK Platform 35, Build-Tools 35.0.0 і Gradle 8.11.1. Збірку виконано стандартними задачами, без вимкнення перевірки Kotlin metadata чи lint.

## Виправлення

У 0.4.0 Firebase BoM 34.19.0 підключав Auth 24.2.0 із метаданими Kotlin 2.3.0, несумісними з Kotlin 2.1.20 у проєкті. У 0.4.1 зафіксовано BoM 33.16.0 / Auth 23.2.1. Перевірено офіційний Auth AAR: метадані Kotlin 2.1.0, SHA-256 `c07f7112a6620c957240a14e1a07d85be0015e403564a5c23312d4dc4e60b7dc`. Kotlin, KSP, AGP та Gradle залишилися попередніми.

## Виконано

- KSP згенерував код Room; Kotlin та Java успішно скомпілювалися. Експортовану схему Room версії 2 включено до вихідного проєкту.
- 32 JVM-тести: 1 авторизації (38 перевірок правил та скасування), 8 підбору, 12 фото-правил, 7 геометрії фото та 4 оформлення. Помилок і пропусків немає.
- Android lint: помилок немає; попереджень — 16. Повний HTML/XML-звіт створюється в `app/build/reports` при збірці.
- Debug APK створено: 66,718,135 байтів, SHA-256 `965f2f5dde80640d24e48017e13ce73c8500e273eddb767763dc07bed28ec52d`. Цей ZIP містить вихідний код; локальний тестовий APK і ключ підпису не вкладені. Збирай оновлення своїм попереднім debug-ключем.
- `check_project.py`: 1020 структурних/XML/resource/SQL перевірок до появи згенерованих файлів; 240 ключів UA/EN/PL, 9 XML, 24 DAO-запити.
- `check_auth.py`: 38 перевірок робочих Java-класів.
- `check_management.py`: SQL-ізоляція, каскадне видалення, rollback та міграція.
- `check_photo_rules.py`: 12 правил і 7 геометричних сценаріїв на робочому коді.
- `check_theme.py`: 120 кольорових пар, мінімальний контраст 4.66:1.
- `check_auth_config.py`: package name, project ID та форма наданої конфігурації перевірені; `google-services.json` збережений байт у байт.
- Оновлювач перевірено Python-моделлю його правил: чиста 0.4.0 → 0.4.1, часткове виправлення BoM, повторний запуск, CRLF, збереження незалежних змін і конфігурації Firebase, відмова при конфлікті до запису й захист уже наявних нових файлів.

## Ще потребує перевірки

31 Android instrumentation-тест включено, але не запущено на телефоні/емуляторі. Реальна авторизація Firebase, реєстрація, доставка reset-листів, UI/TalkBack та ML-моделі на пристрої не перевірялися. Нових Firebase-акаунтів або листів під час цієї роботи не створювали.

Email/Password увімкнений згідно з наданим скриншотом. Парольна політика та email templates зі скриншота не визначаються. PowerShell runtime не запускався; його правила перевірені окремою Python-моделлю. Windows-збірку запускає користувач.

Android-сценарії — AUTHENTICATION.md та ACCEPTANCE.md.
