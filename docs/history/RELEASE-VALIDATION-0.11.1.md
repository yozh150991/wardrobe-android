3 жовтня 2026. `versionCode=16`, `versionName=0.11.1-release`, Room 8, ZIP backup 8.

П’ять `CloudEmulatorTest` використовують два незалежні SDK-клієнти одного UID та окремі Room/фото-каталоги. Перевірено чергу після збою й повторного відкриття БД, втрату відповіді після commit без дублювання, редагування під час upload, три вибори конфлікту та конкурентний compare-and-set. Для вибору хмари створюється ZIP порятунку; для «обидві» перенесені дані отримують окремі ID. Збої ін’єктуються на межі transport, а повторний обмін виконує справжній SDK із локальними серверами.

Фінальні виправлення: правильне звернення до DAO; явна перевірка `resource == null` для незмінного архіву Storage; memory cache Firestore при збереженні офлайн-черги в Room; офіційний Gradle wrapper із двома SHA256-перевірками; debug HTTP тільки для локальних адрес; явне виключення автоматичного системного backup/перенесення при збереженні власних ZIP/хмари. Firebase-конфіг лишився byte-identical. Приватні ключі й локальні SDK-налаштування в пакет не входять.

Ці результати стосуються перелічених автоматичних перевірок; UI-приймання входу не завершено через зависання System UI емулятора. Повне ручне приймання всіх екранів гардероба на фізичних телефонах, камера, реальний ML, TalkBack, OEM-фонові завдання, відкликана сесія та живий Firebase залишаються окремими перевірками. Клієнтський `google-services.json` не дає адміністративного доступу: у цій сесії немає входу власника Firebase CLI, тому production-сервіси/правила й білінг не змінені.

У нових покупок скасування зберігається після перезапуску й перевіряє подальші зміни. Старі покупки без точного початкового receipt зберігають історію, але безпечне постійне скасування для них відновити ретроспективно неможливо.
