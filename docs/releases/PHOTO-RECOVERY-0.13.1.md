# PHOTO-01 — відновлення обробки фото, 0.13.1

Підстава: 08.10.2026 користувач показав Review item, Item 2 of 11, deferred 1,
processing 0. Фото видно; поля назви/категорії не видно. Версія APK невідома.
Точний збій цього випадку **не відтворено**. Підтверджені кодом прогалини:
BatchImporter не зберігав причину/статус ML; причини незбереження були лише біля
полів нижче фото; failed-запис не можна було завершити вручну з новим фото.

## Поведінка

- Фон і тип речі — окремі результати. Якщо тип не розпізнано, категорію можна
  вибрати вручну й зберегти придатне фото, з фоном або після ручного редагування.
- Причина batch-збою доступна в черзі та редакторі й переживає перезапуск
  у межах акаунта. Старі рядки без звіту не отримують вигаданої причини.
- Retry / підготовка моделі, ручні поля, заміна через Gallery/Camera, наявні
  crop/rotate/background tools та Defer/return to queue залишаються доступними.
  Повторна обробка не гарантує кращого результату.
- Недоступний файл потрібно замінити. Відкрити failed-запис можна без вилучення
  з черги; збереження зберігає ID і прибирає тільки цей рядок.
- Біля Save видно, що потрібно виправити: фото, назву, категорію, суму, посилання.
  Валідація й перехід до поля відбуваються до підтвердження дубліката.
- Основна кнопка залишається внизу; другорядні дії прокручуються з формою.
  Дані користувача не відкидаються через ML-помилку.

## Причини та дії

| Встановлена причина | Пояснення / дія |
| --- | --- |
| Немає моделі | Підготувати модель або заповнити вручну. |
| Play services недоступні | Перевірити сервіс; ручне збереження залишається. |
| Об’єкт не відділився від фону | Обрізати, відредагувати вручну, лишити фон чи замінити фото. |
| Timeout | Повторити або перейти до ручних полів; не приписувати причину мережі. |
| Категорія невідома / labeler failed | Вибрати вручну; успішний cutout від цього не стає failed. |
| Немає доступу / файлу | Повторно вибрати чи завантажити доступну копію. |
| Не декодується / понад 25 МБ | Інше фото або зменшена JPG/PNG-копія. |
| Підтверджений ENOSPC | Звільнити місце й повторити. |
| Загальна read/write або невідома помилка | Чесне загальне пояснення, Retry/заміна; без вигаданого діагнозу. |

## Дані й обмеження

Room/backup/cloud залишаються 8. Немає міграції чи зміни формату переносу.
Ownership і фото черги залишаються в наявних сховищах. Діагностика містить
лише ID фото, підказки й коди, без фото/URI/raw exceptions/cache paths.
Вона прибирається після Save/Skip і при recovery для видалених рядків.
Новий batch-прохід замінює звіт. Ручний повтор в редакторі має session state:
після рестарту для зміненого фото не показується старий статус.
Оригінал не додається до постійного архіву; наявні правила cleanup збережені.
