# Редактор фото — 0.13.4

PHOTO-04, code 23, Room/backup 8. Реалізовано у вихідному коді; статус **verify** до Android-приймання. Попереднє очищення фону з 0.13.3 збережено.

## Як користуватися

Відкрийте «Редагувати фото» → фон. Кнопки «Назад» і «Вперед» розміщені над прокручуваними інструментами. Один дотик або безперервний мазок — один крок; відновлення стертої ділянки теж можна скасувати. «Вперед» активна лише після скасування. Новий завершений мазок прибирає скасовану гілку; зміна розміру, зум і скасований жест цього не роблять.

Пензель починається з 16 пікселів. Є точні «−/+» з кроком 1 піксель, повзунок із більшою точністю для малих розмірів і швидкі значення 1/4/16/64/максимум, доступні для поточного фото. Максимум — приблизно 16% короткої сторони фото (164 пкс на 1024×1024), як у попереднього великого пензля. 1–4 пкс призначені для тонкої роботи. Розмір означає діаметр у пікселях зображення й не змінюється від зуму. Дотик без перетягування теж стирає. Для точності збільшіть фото; окремий режим руху не малює.

Обрізання й поворот мають спільну історію: один рух кута або повзунка — один крок, один поворот — один крок. Скидання обрізання і повернення до доступного фото з фоном також можна скасувати в їхньому інструменті.

**Межа історії:** перехід між фоном і обрізанням/поворотом застосовує зроблені зміни та починає нову історію для нового зображення. У вже застосованих попередніх етапах undo недоступне. Якщо всі зміни скасовані й новий файл не потрібен, перехід зберігає наявну гілку redo. Після закриття редактора попередня історія не відновлюється. Не застосовані завершені кроки й позиція redo зберігаються через rememberSaveable при відновленні відкритого редактора; незавершений рух не зберігається.

## Реалізація й межі

- PhotoEditHistory: до 128 команд і 160000 символів; без копій bitmap у SavedInstanceState. PhotoMaskHistory зберігає сегменти кожного мазка один раз; до 2048 сегментів у застосованій історії. Ліміт не стирає старі кроки: можна скасувати крок або застосувати правки й відкрити редактор знову.
- PhotoBrushRules визначає діаметр/радіус. PhotoMaskRules змінює тільки alpha; RGB тканини зберігається. Відновлення повертає пікселі джерела поточного етапу, а не постійно збережений оригінал.
- Попередній перегляд і збереження використовують однакову роздільність. Однопіксельний дотик потрапляє в найближчий піксель, зокрема на межі між пікселями. Поки новий preview обчислюється, показано останній результат та індикатор; Apply чекає відповідного результату.
- Скасування pointer-жесту або другий палець прибирає весь незавершений мазок. Вихід за фото не малює вздовж штучно затиснутого краю. Повернення всередину починає нову ділянку цього ж мазка.
- Перемикання інструментів під час мазка заблоковано; при переході зроблені правки передаються наступному інструменту. Помилка/скасування файлової операції залишає поточний інструмент та історію.
- Нових постійних полів, дозволів, API й оригіналів немає. Тимчасові варіанти використовують наявні PhotoStore/trackDraft та очищення. UA/EN/PL/fallback: 11 нових рядків.

## Виконані перевірки

17 host-наборів пройшли. 1774 Java assertions перевіряють immutable-історію, межі undo/redo, нову гілку, захист від зовнішньої зміни масивів, збереження курсора, ліміти, усі розміри повзунка, 1-піксельні дотики на фото 1–1024 пкс, суцільну тонку лінію, великий пензель, точкове відновлення, незмінність RGB/джерела й cancellation. Це логіка production-класів, не емуляція Compose touch.

Підготовлено JUnit wrapper і 5 Android-тестів JSON/історії: цілий мазок, серіалізація redo та розмірів, повернення джерела, pending-жест і пошкоджений envelope. Gradle JUnit та Android-тести не запущено. Збірка зупинилася до компіляції: UnknownHostException: services.gradle.org. APK відсутній.
