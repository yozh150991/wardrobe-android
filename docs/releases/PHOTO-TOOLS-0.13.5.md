# Редактор фото — 0.13.5

PHOTO-05, code 24, Room/backup 8. Лупа, спільна історія та м'який пензель реалізовані у вихідному коді; статус **verify** до Android-приймання. Очищення фону, білий/кремовий фон і точний розмір пензля з попередніх версій збережені.

## Як користуватися

У ручному редагуванні фону лупа показує ділянку під пальцем зі збільшенням 3×. Зазвичай вона зверху; біля краю переміщується, щоб залишатися всередині полотна. Є перемикач лупи. Зум фото й окремий режим руху залишаються доступними.

Пензель має діаметр від 1 пкс до попереднього великого розміру, **м'якість 0–100%** і **силу 1–100%**. Нульова м'якість дає чітку межу, більша — плавний край. Менша сила частково стирає або відновлює прозорість. За замовчуванням край чіткий і сила 100%. У межах одного мазка перекриття сегментів не посилює дію; новий окремий мазок може посилити ефект. Колір тканини не змінюється.

«Назад» і «Вперед» тепер спільні для **стирання, відновлення, обрізання, повороту та повернення джерела**. Можна стерти фон, повернути фото, обрізати, повернутися до пензля й скасувати всі ці дії по черзі. Перемикання інструмента не створює файл і не обнуляє історію. Завершений мазок, рух кута або повзунка обрізання — один крок. Після відпускання обрізане фото вписується в полотно; розширити відрізану ділянку можна через «Назад».

Нова завершена дія після скасування прибирає стару гілку «Вперед». Зміна налаштувань, зум, перемикання інструмента й скасований жест зберігають її. Скидання всіх змін і повернення доступного фото з фоном теж можна скасувати. Налаштування пензля зберігаються при переході між інструментами.

«Застосувати» зберігає результат один раз; «Скасувати» залишає фото без змін. Після закриття редактора попередня історія не доступна. Завершені команди та курсор redo зберігаються для відновлення відкритого редактора; незавершений мазок не зберігається. Постійна копія оригіналу не створюється.

## Реалізація та межі

- PhotoSessionRules і PhotoSession відтворюють однакову послідовність для preview та PNG. Обрізання/поворот перетворюють і зображення, і доступні пікселі відновлення. Відновлення не вигадує деталі, яких уже немає в джерелі сесії.
- Попередній preview можна використати для наступної команди лише для того самого PhotoStore та джерела; undo/redo відтворюють потрібну історію. Кешований кадр «до» також показується лише для поточного frame. «Застосувати» чекає актуального результату. Помилка лишає історію, доступні undo та повтор.
- PhotoMaskRules змінює alpha, зберігає RGB; плавний край і часткова сила однакові в preview та replay. Один мазок накопичує максимальне покриття пікселя, незалежно від кількості pointer-подій.
- До 128 команд, 160000 символів і 2048 сегментів застосованої історії; старі кроки не видаляються мовчки. Після ліміту можна скасувати крок або застосувати й відкрити редактор знову. Декодування обмежено 16 млн пікселів; продуктивність на межі потребує вимірювання на Android.
- Новий файл створюється тільки при застосуванні; порожній прозорий результат відхиляється. Скасовані/невдалі кандидати очищуються наявним PhotoStore, фінальний результат відстежується як чернетка. Room, backup, permissions та постійні оригінали не змінені.
- UA/EN/PL/fallback: 9 нових рядків, 911 загалом. Нових ML-моделей чи платних API немає.

## Виконані перевірки

17 host-наборів пройшли: 3824 source/SQL checks, 11 XML, 911 рядків, 67 DAO. У production Java — 22649 нових assertions: м'які краї, сила, незалежність від частоти подій, RGB/alpha, змішаний порядок операцій, undo/redo/нова гілка, трансформація пікселів відновлення, cancellation і положення лупи. Збережені 1774 попередні assertions редактора. Перевірено кадр 1600×1200 із тонкими мазками під -Xmx256m; це не оцінка native-продуктивності.

PhotoSessionTest містить 4 JUnit-методи, PhotoSessionPersistenceTest — 5 Android-тестів для JSON/redo/стилю, reset джерела, збігу preview і збереженого PNG, incremental replay та очищення порожнього кандидата. Вони підготовлені, але Gradle runner не виконаний. Bootstrap Gradle завершився до компіляції: UnknownHostException: services.gradle.org. Kotlin/Compose, Android-жести й APK не перевірені.

## Матриця Android-приймання — ще не виконана

Спочатку testDebugUnitTest, lintDebug, assembleDebug, connectedDebugAndroidTest. У матриці 0.13.4 стару межу історії між інструментами замінює нова поведінка нижче.

| Сценарій | Очікувана поведінка |
| --- | --- |
| Стерти → повернути → обрізати → відновити → undo/redo всіх кроків | Точні проміжні та кінцеві зображення; історія не скидається при зміні інструмента. |
| Undo → інший інструмент/налаштування/зум → redo | Стара гілка доступна; попередній мазок має власний розмір, м'якість і силу. |
| Undo → новий мазок/обрізання | Попередня гілка redo недоступна; нову дію можна скасувати. |
| Край тканини: 1/4 пкс, м'якість 0/50/100%, сила 1/25/100% | Плавний контроль краю, збережений RGB; повільний та швидкий рух однаково діють на покриті пікселі. |
| Два окремі слабкі мазки й один із повторним проходом | Окремі мазки посилюють дію; сегменти одного не накопичують непрозорість. |
| Лупа при 1×/8×, в усіх кутах, portrait/landscape | Показує поточну ділянку й перехрестя; не виходить за полотно; перемикач працює. |
| Другий палець, скасування жесту, вихід за фото/полотно | Pending-мазок скасовується при перериванні, redo зберігається; за межами фото немає смуги. |
| Обрізання кутами й повзунками, включно зі скасуванням | Один завершений рух — один крок; немає завислих disabled-кнопок чи часткового збереження. |
| Скинути все / повернути доступне фото з фоном → undo/redo | Повертається відповідне джерело та всі попередні дії. |
| Поворот екрана / відновлення відкритого редактора | Завершена історія, redo та налаштування відновлені; незавершений мазок відсутній. |
| Apply, Cancel, прозорий результат, помилка/скасування запису | Preview і PNG збігаються; джерело не змінюється; невдалі кандидати не лишаються. |
| Заміна фото й зміна акаунта під час обчислення | Пізній preview/результат не показує й не змінює інший акаунт або чернетку. |
| Довгі мазки, ліміти, найбільше допустиме фото | Виміряти час/пам'ять на пристрої; немає ANR/OOM, видимий ліміт та доступне undo/apply. |
| UA/EN/PL, 320 dp, 200% шрифт, теми, TalkBack | Основні дії доступні, повзунки мають зрозумілі підписи, вміст прокручується. |
