## Навіщо

Після виправлення QA-61-30 фото з галереї обробляються, але на телефоні користувача видно дві вади вирізання:
на светрі лишилися шматки червоного покривала, а до сорочки «приклеїлася» нога з кадру. Пороги правил
(`PhotoCutoutRules`) досі підбиралися на синтетичних масках. Щоб налаштувати їх на справжніх, потрібні маски моделі
ML Kit із телефону.

## Що змінилося

Лише debug-збірка. Після кожної обробки фото застосунок зберігає три PNG у свою зовнішню теку `photo-debug/`:

| Файл | Що в ньому |
| --- | --- |
| `<час>-source.png` | Пікселі, які отримали правила (фото після зменшення для аналізу) |
| `<час>-mask.png` | Впевненість моделі, обрізана до 0–1, 16 біт: червоний канал — старший байт, зелений — молодший |
| `<час>-cutout.png` | Результат вирізання |

- «Очистити фон сильніше» дає файли з позначкою `-stronger`.
- Зберігаються лише 8 останніх знімків; старіші видаляються.
- Release-збірка нічого не пише: перевірка `FLAG_DEBUGGABLE` стоїть до будь-якого запису.
- Збій запису не впливає на обробку фото. Нових дозволів немає.

Файли: photo/PhotoDebugCapture.kt, photo/PhotoAnalyzer.kt, tools/check_photo_capture.py.
