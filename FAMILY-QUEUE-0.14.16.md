# FAM-03 — черга правок речей, 0.14.16 / code 46

Статус: реалізація verify; CI цього PR і спільне native-приймання окремо.
Гілка `feat/family-edit-queue-0.14.16` поверх PR #13 (спільні образи).

## Поведінка

Owner/editor зберігає назву, розмір, місце й опис кількох спільних речей.
Одна незавершена правка на річ, до 100 правок на акаунт. Відкриття іншої речі
більше не підміняє її першою незавершеною правкою гардероба. Збереження,
перебазування й повтор не змінюють порядок; видалення зачіпає тільки вибрану правку.
У перегляді спільного гардероба доступна «Черга правок речей», кількість, список
із назвами й перехід до редактора. Незбережені поля блокують перемикання та batch send.

«Надіслати зміни» обробляє першу правку, «Надіслати всю чергу» після підтвердження
обробляє поточний список вибраного гардероба послідовно. Нові операції не підхоплюються
в уже підтверджений пакет. Це явне надсилання, не фонова/автоматична синхронізація.

Перед першим надсиланням кожної правки отримується поточний snapshot. Незмінені
користувачем поля залишаються серверними; зміни різних полів об’єднуються. Якщо
серверне значення зміненого поля відрізняється і від початкового, і від локального,
черга зупиняється: наявне порівняння та явне підтвердження мають вирішити конфлікт.
Уже застосовані значення не надсилаються повторно. Видалена річ не відновлюється.

Перед мережевим запитом зберігається точний submitted request. Втрата відповіді,
некоректний receipt, закриття акаунта або переривання зберігають той самий editId,
baseRevision і changes. Після рестарту спочатку повторюється саме цей запит —
без refresh/rebase його payload. Лише підтверджений receipt дозволяє вилучити
операцію й перейти до наступної. Серверний CAS захищає від гонки після refresh.
Помилка будь-якої операції зупиняє пакет; решта зберігається.

## Дані та сумісність

- Account-private AtomicFile `family-edits/<account>/outbox.json`: формат v2.
- v1 читається без зміни; наступний успішний запис атомарно переводить його у v2.
  Старі submitted UUID/payload не змінюються під час міграції.
- CAS за повною очікуваною чернеткою та парою remote/item; глобально унікальні editId.
- Пошкоджений, чужий, завеликий або невідомий формат відхиляється без очищення даних.
- Старий клієнт не підтримує v2; downgrade не підтримується і не має стирати outbox.
- Room/backup залишаються 10; приватний гардероб, фото та portable backup не змінені.
- Нових backend endpoints, правил або production deployment немає.

## Перевірки

- 22 нових JVM-тестів: FIFO/CAS/межі 100–101, кілька гардеробів, міграція v1,
  submitted recovery, конфлікт/видалення, незалежні поля, already-applied,
  account cancellation, незмінний пакет, double tap і no-op старого клієнта.
- 2 нових instrumented store tests (разом 7): кілька речей після restart,
  атомарна міграція з незміненим submitted request. Не виконані на пристрої.
- Host runner: 23 suites pass, Firebase client config skipped; backend 148 pass. Android CI — перевірити для PR.
- Попередній PR #13: CI 39999768334 успішний (unit/lint/preview APK),
  це доказ лише для його commit 8603ee7, не для цієї черги.

## Спільне native-приймання

1. Змінити 3 різні речі, зберегти кожну, закрити/перезапустити; перевірити порядок і поля.
2. Редагувати середню чернетку, видалити останню: решта й порядок не змінюються.
3. Надіслати всю чергу; на другому акаунті після refresh видно всі зміни.
4. Конкурентно змінити незалежне поле й те саме поле: merge проти явного conflict.
5. Втратити мережу/відповідь, змінити акаунт під час надсилання; retry без дубля.
6. Viewer/revoke, lease/background, 100/101 правок, UA/EN/PL, 320 dp, 200%, TalkBack.
