# Wardrobe 0.13.8 — краї, ласо та відновлення редактора

PHOTO-12–14, code 27, Room/backup 8. Реалізовано у джерелах, статус verify.
За вказівкою користувача native-приймання виконаємо разом. Нового APK немає.

## Користування

Річ → Редагувати фото → «Краї та ласо».

- «Краї маски»: зміщення −8…+8 пкс і згладжування 0…6 пкс. Перегляд до цього
  кроку, масштаб до 8×, переміщення і контрастні підкладки. Крок потрібно
  підтвердити окремою кнопкою; нульові/порожні зміни не додаються до історії.
- Ласо: послідовні дотики задають 3–128 вершин полігона. Для точного або
  доступного введення є X/Y повзунки й «Додати точку». Останню вершину можна
  прибрати, весь контур — очистити. Самоперетини використовують even-odd fill.
- Дії: стерти, відновити, захистити, зняти захист. Відновлення обмежене
  доступним джерелом сесії; видалений до сесії фон/деталі не реконструюються.
- Бірюзовий overlay позначає захист. Він діє на пензель (також відновлення),
  суміжну ділянку фону, ласо та alpha-краї. Захист є бар’єром для flood fill.
  Обрізання може прибрати захищену ділянку, поворот/обрізання переносять маску,
  скидання джерела очищає її. Ці операції також скасовуються Undo.
- Один підтверджений крок — одна дія спільної історії. Undo/Redo охоплюють
  захист, очищення, геометрію та reset. Новий крок після Undo прибирає redo-гілку.

## Збереження і відновлення

Кожен підтверджений крок, Undo/Redo і вибір інструмента записується в чинну
приватну чернетку речі. Історія зберігає команди та ID потрібних джерел, без
нового набору bitmap-копій. Автозбереження полів не стирає recipe. Інша річ або
інше фото не отримують чужої історії; інший акаунт має окремі prefs і photos.

«До форми, зберегти чернетку» або Back зберігають історію. На формі є
«Продовжити редагування фото». Перед Save речі потрібно Apply або явне
«Відкинути правки фото»; заміну фото й автообробку відкладено до цього.
Непідтверджені previews/контур і незавершений жест не є кроками. Кнопки
Apply/виходу до форми блокуються до підтвердження/очищення preview. Після
аварійного завершення відновлюються підтверджені кроки, а не preview/zoom/brush.

Apply резервує ID у cleanup ledger до створення PNG. Після успішного PNG
новий ID і видалення recipe фіксуються одним commit чернетки, до callback UI.
Старий SavedInstanceState не підміняє новіший photo/history. Owner/photo guards
відхиляють застарілий результат; помилка/скасування прибирають новий кандидат.
Старе збережене фото речі змінюється лише після її звичайного Save.

Посилання source/reset/redo/before захищені від очищення, поки потрібні сесії;
попередні джерела записані у спільний cleanup ledger разом із recipe. Після
Apply/Discard/завершення чернетки непотрібне прибирає існуючий механізм. Якщо
файл потрібен іншій речі, його не видаляють. Backup/cloud формат не змінений;
portable backup не переносить локальну recipe. Cloud apply вже чекає завершення
локальних чернеток. Пошкоджену recipe показуємо як помилку, зберігаючи фото й
опис до явного discard. Помилка запису видима; вихід не імітує успішне збереження.

## Фактичні докази

18 host-наборів у docs/history/HOST-VALIDATION-0.13.8.json пройшли. PhotoPrecisionCases
компілює production Java та виконує 588864 assertions: незалежний raster oracle
для alpha min/max/blur, границі полігонів, RGB/alpha/source незмінність, захист
усіх інструментів, crop/rotate, прозорі/захищені бар’єри та cancellation.
Synthetic 2048² проходить -Xmx256m; час у журналі є host-вимірюванням, не Android.
Попередні photo suites і реальні SQL guards також пройшли.

Підготовлено PhotoDraftRecoveryTest (8 Android-тестів) і PhotoPrecisionTest
(JUnit wrapper). Native тести перевіряють справжні prefs/PNG/Room, account scope,
redo/merge/неправильний рецепт/cleanup/preview-export. Вони **не виконувалися**.
Kotlin/Compose/KSP/Gradle/JUnit/lint/assemble/телефон/емулятор не запускалися.
Не перенось успіх історичного APK на поточні джерела.

## Спільна матриця приймання

| Сценарій | Очікування |
| --- | --- |
| Білий одяг, темний контур, ремінці/шнурки, розміри 1/32/1024/2048 | RGB не перефарбовані; alpha змінюється передбачувано, край не створює відсутні деталі; тонкі частини видимі у preview |
| Slider швидко туди-назад, undo/redo, crop → protect → rotate → erase | Preview і PNG однакові; один крок на підтвердження; захист лишається на правильних пікселях |
| Полігон 0/1/2/3/128 точок, самоперетин, точки по краях | До 3 точок підтвердження недоступне; 129-та не додається; виділення узгоджене з preview |
| Захист → brush erase/restore, flood fill, lasso, edges | Захищені RGBA незмінні; flood fill не перетинає захист; скасування відновлює точну маску |
| Повне видалення, плоский/порожній полігон, відсутні alpha для expansion | Немає підтвердження порожнього результату або no-op; пояснення видиме |
| Back/закрити → відновити чернетку, force-stop, rotate device | Та сама підтверджена історія/redo/джерело/інструмент, поля речі збережені |
| Kill до PNG, після PNG, після commit перед callback | Чернетка або старе джерело з повною історією, або новий кінцевий файл; кандидат відомий cleanup ledger |
| Немає місця, нечитабельна recipe/джерело, скасування Apply | Немає тихої втрати фото чи удаваного успіху; доступні повтор/явний discard, старий запис речі цілий |
| Назва/ціна змінюються при закритому редакторі з чернеткою фото | Поля й recipe співіснують; Save відкриває незавершений редактор, доки немає Apply/Discard |
| Sign out A → B → A, повторне використання ID іншої речі | Чужі файли/історія не відкриваються; late Apply не пише до нової чернетки |
| Два записи зі спільним фото, redo reset source, завершення чернетки | Потрібні джерела не видалені; зайві тимчасові файли прибрані після звільнення references |
| UA/EN/PL, 200% шрифт, 320dp/landscape, TalkBack | Прокрутка всього діалогу при малому місці; кнопки/координатні контролі досяжні, підписи не обрізані |
| 128 кроків/160000 символів, багато великих фото | Межі історії чесні, новий крок після Undo відкидає redo; заміряти peak heap/latency/GC на Android |
