# Мій гардероб: перше збирання та встановлення на Windows

Гайд для архіву `wardrobe-android-0.1.0-source.zip`. Перевірено за файлами проєкту 21 вересня 2026 року. Команди збирання тут ще не виконувалися: середовище створення не має Android SDK. Перше збирання може виявити помилки коду — це не обов’язково помилка налаштування твого ноутбука.

Мета: отримати `app-debug.apk`, встановити його та перевірити роботу на кількох тестових речах. Поточна версія локальна: без входу, GCP-синхронізації та автоматичного аналізу фото.

## 1. Що підготувати

- Ноутбук із 64-бітною Windows, інтернет і телефон Android 8.0 або новіший.
- Кабель USB з передаванням даних, якщо встановлюватимеш через комп’ютер.
- Бажано зарезервувати приблизно 15–20 ГБ вільного місця для інструментів, кешів і проєкту. Це практичний запас, а не точний розмір завантаження.
- Для першого налаштування заплануй орієнтовно 1–2 години: час залежить від інтернету й ноутбука.

Для цього першого запуску використовуємо справжній телефон. Емулятор не обов’язковий.

## 2. Розпакуй проєкт

1. Завантаж архів вихідного коду з нашого чату на ноутбук.
2. Створи `C:\Projects` у Провіднику Windows.
3. Натисни правою кнопкою на ZIP → **Extract All / Видобути все**.
4. Як місце розпакування обери `C:\Projects`. Архів уже містить папку `wardrobe-android`.
5. Перевір, що файл скрипта лежить саме тут:

```text
C:\Projects\wardrobe-android\build-apk.ps1
```

У цій самій папці мають бути `settings.gradle.kts`, `build.gradle.kts`, `README.md` і підпапка `app`. Якщо утворилася зайва вкладена папка, перенеси внутрішню `wardrobe-android` у `C:\Projects`.

Працюй із розпакованими файлами. Сам ZIP не є проєктом для запуску.

## 3. Встанови Android Studio та Android SDK

1. Завантаж стабільну Android Studio для Windows з [офіційної сторінки](https://developer.android.com/studio).
2. Запусти інсталятор `.exe`, заверши встановлення та відкрий програму.
3. Пройди майстер першого запуску, погодь встановлення SDK. Якщо є вибір імпорту старих налаштувань і це перше встановлення, обери **Do not import settings**.
4. Дочекайся завершення завантажень. Новий порожній Android-проєкт створювати не потрібно.

Цей процес описаний в [інструкції встановлення Android Studio](https://developer.android.com/studio/install).

На початковому екрані знайди **More Actions → SDK Manager**. Якщо вже відкрито проєкт, скористайся **Tools → SDK Manager**. Назви та розташування пунктів можуть трохи відрізнятися між версіями.

У **SDK Platforms** встанови **Android 15 / API 35 → Android SDK Platform 35**. У **SDK Tools** увімкни **Show Package Details** та встанови:

| Компонент | Що обрати |
|---|---|
| Android SDK Build-Tools | Саме `35.0.0` |
| Android SDK Platform-Tools | Доступну актуальну версію |
| Android SDK Command-line Tools | `latest` |

Натисни **Apply**, прийми ліцензії та дочекайся завершення. SDK Manager показує **Android SDK Location** — запиши цей шлях. Зазвичай це `C:\Users\ТВОЄ_ІМ’Я\AppData\Local\Android\Sdk`. Керування компонентами описано в [офіційній документації SDK Manager](https://developer.android.com/studio/intro/update).

API 35 потрібний для збирання цього проєкту навіть тоді, коли на телефоні встановлений Android 16. Версію Android телефона змінювати не потрібно.

## 4. Встанови JDK 17

Щоб не залежати від версії Java, вбудованої у твою Android Studio, для цього гайда використовуємо окрему JDK 17.

1. Відкрий [Eclipse Temurin 17 для Windows x64](https://adoptium.net/temurin/releases/?version=17&os=windows&arch=x64).
2. Обери **JDK**, версію **17**, **Windows**, **x64** та інсталятор **MSI**. Потрібна JDK, а не лише JRE.
3. Встанови її й запиши каталог встановлення. Він може виглядати як `C:\Program Files\Eclipse Adoptium\jdk-17.0.xx.x-hotspot` — точні цифри залежать від завантаження.

У корені цього каталогу є папка `bin`, а в ній `java.exe` і `javac.exe`. Для `JAVA_HOME` потрібен шлях до каталогу JDK без `\bin`.

У проєкті зафіксовано Android Gradle Plugin `8.9.2`, Gradle `8.11.1`, Kotlin `2.1.20` і SDK `35`. Поєднання Gradle 8.11.1, Build-Tools 35.0.0 та JDK 17 відповідає [таблиці сумісності AGP 8.9](https://developer.android.com/build/releases/agp-8-9-0-release-notes). До першого успішного збирання залиш ці версії без змін.

## 5. Підготуй PowerShell

Відкрий меню **Пуск**, введи **PowerShell** і запусти звичайне вікно. Для збирання права адміністратора не потрібні.

Перейди в проєкт:

```powershell
cd C:\Projects\wardrobe-android
```

Задай шлях до Java. **Замінити треба весь приклад нижче на фактичний каталог із кроку 4:**

```powershell
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\ТУТ_ТОЧНА_НАЗВА_ПАПКИ_JDK_17'
```

Для стандартного розташування SDK:

```powershell
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
```

Якщо SDK Manager показував інший шлях, використай саме його, наприклад:

```powershell
$env:ANDROID_HOME = 'D:\Android\Sdk'
```

Виконай перевірку:

```powershell
& "$env:JAVA_HOME\bin\java.exe" -version
& "$env:JAVA_HOME\bin\javac.exe" -version
Test-Path "$env:ANDROID_HOME\platforms\android-35\android.jar"
Test-Path "$env:ANDROID_HOME\build-tools\35.0.0\aapt2.exe"
Test-Path .\build-apk.ps1
```

Очікується: обидві версії Java починаються з `17`, а всі три перевірки `Test-Path` повертають `True`. Якщо бачиш `False`, спочатку виправ відповідний шлях або встанови компонент SDK.

Ці змінні діють лише в поточному вікні PowerShell. Після його закриття їх треба задати знову. Усі подальші команди вводь у цьому самому вікні.

## 6. Виконай перше збирання

```powershell
.\build-apk.ps1
```

Скрипт із нашого архіву завантажить Gradle 8.11.1, перевірить його контрольну суму, створить Gradle Wrapper і запустить три задачі: `testDebugUnitTest`, `lintDebug`, `assembleDebug`.

Під час першого запуску завантажуються бібліотеки. Чекай завершення процесу, не закривай вікно. Має з’явитися **BUILD SUCCESSFUL** для фінального збирання. Скрипт також може показати окремий успіх створення Wrapper раніше — це ще не готовий APK.

Після успішного завершення перевір:

```powershell
Test-Path .\app\build\outputs\apk\debug\app-debug.apk
```

Має повернутися `True`. Відкрити папку можна командою:

```powershell
explorer.exe .\app\build\outputs\apk\debug
```

Повний шлях до інсталятора:

```text
C:\Projects\wardrobe-android\app\build\outputs\apk\debug\app-debug.apk
```

Якщо є **BUILD FAILED**, перейди до кроку 11. Не вважай збирання успішним лише через наявність APK від попередньої спроби.

## 7. Якщо Windows блокує PowerShell-скрипт

Цей крок потрібний лише для повідомлення на кшталт `running scripts is disabled` або `not digitally signed`. Можна виконати ті самі задачі через офіційний Gradle без зміни політики PowerShell.

1. На [офіційній сторінці Gradle](https://gradle.org/releases/) знайди **8.11.1** та завантаж **binary-only** (`gradle-8.11.1-bin.zip`).
2. Перед розпакуванням обчисли SHA-256, указавши справжній шлях до завантаженого ZIP:

```powershell
Get-FileHash "$env:USERPROFILE\Downloads\gradle-8.11.1-bin.zip" -Algorithm SHA256
```

Для цього архіву в проєкті зафіксована контрольна сума:

```text
f397b287023acdba1e9f6fc5ea72d22dd63669d59ed4a289a29b1a76eee151c6
```

Якщо вона не збігається, цей файл не використовуй. Великі й малі літери в записі суми означають те саме.

3. Розпакуй у `C:\Tools`, щоб з’явився файл `C:\Tools\gradle-8.11.1\bin\gradle.bat`.
4. У PowerShell із налаштованими `JAVA_HOME` та `ANDROID_HOME` виконай:

```powershell
cd C:\Projects\wardrobe-android
& 'C:\Tools\gradle-8.11.1\bin\gradle.bat' wrapper --gradle-version 8.11.1 --distribution-type bin --gradle-distribution-sha256-sum f397b287023acdba1e9f6fc5ea72d22dd63669d59ed4a289a29b1a76eee151c6
```

Якщо ця команда завершилася успішно, виконай:

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

Не переходь до наступної команди, якщо попередня завершилася помилкою. Вихідний APK буде в тій самій папці з кроку 6. У керованому робочому середовищі дотримуйся правил адміністратора щодо запуску інструментів.

## 8. Встанови APK на телефон

**Варіант А — відкрити APK на телефоні.** Передай `app-debug.apk` через USB у папку Downloads телефона. Відкрий його файловим менеджером, наприклад «Мої файли». Якщо Android попросить дозвіл установлення для цього файлового менеджера, надай його для встановлення власного APK. Після встановлення дозвіл можна вимкнути. Якщо показано інший тип блокування, зафіксуй точний текст: не всі повідомлення означають відсутність цього дозволу.

**Варіант Б — встановити через USB із ноутбука.** Цей спосіб також потрібний для Android-тестів і діагностики.

1. На Samsung відкрий **Налаштування → Відомості про телефон → Відомості про ПЗ → Номер збірки**; назви можуть дещо відрізнятися. Натисни номер сім разів і підтвердь PIN, якщо його запитають.
2. Відкрий **Параметри розробника** та ввімкни **Налагодження USB / USB debugging**. Див. [налаштування режиму розробника](https://developer.android.com/studio/debug/dev-options).
3. Підключи розблокований телефон кабелем для даних. На телефоні підтвердь дозвіл USB debugging для свого ноутбука.
4. У тому самому PowerShell виконай:

```powershell
& "$env:ANDROID_HOME\platform-tools\adb.exe" devices
```

Біля серійного номера має бути `device`. `unauthorized` означає, що треба підтвердити запит на телефоні. Якщо список порожній, перевір кабель і USB-порт; для Samsung за потреби встанови [офіційний USB-драйвер](https://developer.samsung.com/android-usb-driver).

Коли підключений лише один телефон і немає запущених емуляторів:

```powershell
& "$env:ANDROID_HOME\platform-tools\adb.exe" install -r .\app\build\outputs\apk\debug\app-debug.apk
```

Очікується `Success`. Відкрий «Мій гардероб» на телефоні. Підключення фізичних пристроїв описано в [документації Android](https://developer.android.com/studio/run/device).

Якщо виникла помилка несумісного підпису, не видаляй попередню версію з особистою колекцією до створення резервної копії.

## 9. Перевір додаток на тестових речах

Почни з трьох речей: футболки, штанів і взуття. Перший каталог має бути порожнім; демонстраційні речі з прототипу сюди не переносяться.

| Дія | Очікуваний результат |
|---|---|
| Додати фото з галереї та з камери | Фото видно в картці й каталозі |
| Увести розмір, опис і місце | Значення зберігаються після редагування |
| Закрити додаток і перезапустити телефон | Речі та фотографії залишаються |
| Підібрати комплект до штанів | Початкові штани залишаються, інші речі беруться зі свого гардероба |
| Натиснути «Вдягнув сьогодні» | З’являється відмітка носіння |
| Змінити мову | Доступні українська, англійська та польська |
| Створити другий гардероб | Його речі відокремлені від першого |
| Зберегти копію з фото | Створюється ZIP у вибраному місці |

Для відновлення тестової копії: **Налаштування → Відновити з копії**. Поточна реалізація додає окремі гардероби. Повторний імпорт не об’єднує їх автоматично.

Повний перелік ручних перевірок є в `ACCEPTANCE.md` у проєкті. Масове внесення 200+ речей доцільне після перевірки збереження та відновлення на невеликій колекції.

## 10. Відкриття проєкту в Android Studio та автоматичні тести

Після успішного створення Wrapper відкрий Android Studio → **Open** → `C:\Projects\wardrobe-android`. Обирай корінь проєкту, а не `app`.

У **File → Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK** вибери JDK 17 з кроку 4. Якщо її немає у списку, додай шлях до встановленої JDK. Java для запуску самої Android Studio може залишатися стандартною. Вибір Java для IDE та командного рядка пояснює [документація JDK для Android](https://developer.android.com/build/jdks).

Дочекайся Gradle Sync. Пропозицію оновити AGP поки відклади. Для запуску вибери конфігурацію `app`, свій телефон і **Run ▶**.

Початковий скрипт уже запускає 8 JVM-тестів та lint. Ще 5 тестів потребують Android-пристрою. На підключеному тестовому телефоні чи емуляторі запусти:

```powershell
.\gradlew.bat connectedDebugAndroidTest
```

Звіти після виконання шукай у:

```text
app\build\reports\tests\testDebugUnitTest\index.html
app\build\reports\lint-results-debug.html
app\build\reports\androidTests\connected\
```

Успішне збирання не замінює перевірки камери, зручності екранів і збереження даних на твоєму телефоні.

## 11. Якщо виникла помилка

| Повідомлення або симптом | Що перевірити |
|---|---|
| `build-apk.ps1 is not recognized` | Поточну папку та наявність `build-apk.ps1`; правильна команда — `.\build-apk.ps1` |
| `running scripts is disabled` / `not digitally signed` | Скористайся кроком 7 |
| `JAVA_HOME` invalid / `javac.exe` не знайдено | Шлях до кореня встановленої JDK 17, без `bin` |
| `Unsupported class file major version` | Перевір фактичну Java командою з кроку 5; для цього проєкту обери JDK 17 також у Gradle JDK |
| `SDK location not found` | `ANDROID_HOME` має збігатися з SDK Location |
| `Failed to find Platform SDK` / `android-35` | Установи Android SDK Platform 35 |
| Build Tools `35.0.0` missing | Установи цю точну версію через Show Package Details |
| `License ... not accepted` | Заверши встановлення відповідного SDK-компонента й прийняття ліцензії через SDK Manager |
| `Could not resolve` / timeout / TLS | Збережи адресу ресурсу та текст помилки; перевір інтернет і налаштування проксі, не вимикай перевірку сертифікатів |
| `Gradle checksum mismatch` | Не запускай завантажений архів; потрібна повторна перевірка завантаження |
| `Unresolved reference`, Kotlin compilation failed, KSP error | Надішли повідомлення з назвою файлу й номером рядка — це може бути помилка вихідного коду |
| `Lint found errors` / test failed | Надішли конкретний пункт звіту; не вимикай перевірки для отримання «успіху» |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | Найімовірніше, встановлена версія має інший підпис. Спочатку резервна копія, потім узгодження ключа |
| Додаток одразу закривається | Android Studio → Logcat, вибери телефон і пакет `com.familywardrobe.app`, скопіюй помилку падіння |

Для докладнішого журналу, якщо Wrapper уже створений:

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug --stacktrace --console=plain 2>&1 | Tee-Object -FilePath .\build-log.txt
```

Надішли перше змістовне повідомлення про помилку, блок **What went wrong** і приблизно останні 50–100 рядків журналу. Для помилок Kotlin важливі також рядки, що починаються з `e:`. Якщо проблема в інтерфейсі встановлення, підійде скриншот із назвою кроку. Паролі, ключі та приватні фото не потрібні.

## 12. Оновлення й перенесення даних

Перед оновленням або перевстановленням: **Налаштування → Зберегти копію з фото**. Скопіюй ZIP також на ноутбук. Копія містить фотографії та описи й не зашифрована.

Нову версію з тим самим ідентифікатором пакета та ключем підпису встановлюй поверх старої. Не видаляй додаток і не очищуй його дані як перший спосіб усунення помилки.

Стандартний debug-ключ створюється на ноутбуці в `%USERPROFILE%\.android\debug.keystore`. Збереження цього файла допоможе встановлювати наступні debug-збірки поверх попередніх після перенесення середовища. Для майбутнього поширення потрібний окремий release-підпис.

Хмарного відновлення в цій версії немає. Перенесення на інший телефон виконується через ZIP-копію. Реалізацію входу, сімейного доступу та GCP-синхронізації буде додано на наступних етапах.
